# CRSM 十分钟演示脚本（S7 / FE-24，2026-10-26）

> 面向"向他人展示这个系统能做什么"的场景设计。全程离线、无真实个人信息（演示数据用
> `samples/` 脱敏样例或演示备份）。每步标注预期现象——演示即验收。

## 准备（演示前 2 分钟）

- 断网（演示离线能力）
- 安装包安装的 CRSM（或 `npm run tauri dev`）
- 三个脱敏样例课表：`samples/示例学生A/B/C.xlsx`；准备一个损坏文件（随意改后缀）与 A 的副本（演示批量导入的跳过/拒绝）
- 若需"已有数据"的演示：数据管理页导入演示备份后重启

## 第 1 幕：批量导入与数据质量（2 分钟）

1. 「课程表管理」→ 选择课程表文件（**多选**）：A、B、C + 一个损坏文件 + A 的副本 → 批量结果对话框逐项显示：3 成功 / 1 失败（无法解析）/ 1 跳过（同内容重复）。
2. 讲解点：**逐项结果**、同内容去重、"不同文件争同一学号"会被明确拒绝（可现场复制 A.xlsx 改一个字节再导一次演示冲突提示）。
3. 「助理管理」：课表状态列——未导入课表的人标"未导入"，提供「确认无课」按钮（点一下，状态变绿）。

## 第 2 幕：规则与一次排好 17 周（2 分钟）

1. 「排班配置」：指认关键约束——每周节数口径、最少连续节数、同时段人数、每日均衡；试着把"最少"填成 -3 保存 → **被拦截**（严格校验）。
2. 「排班表」→ 生成（全量）：**进度条**出现（Web Worker），点「取消计算」一次展示即时终止、数据零影响；再生成一次。
3. 结果：17 周方案汇总表（未满足时段/变动/耗时）、每人工时；写入全部周。

## 第 3 幕：手动调整 + 撤销重做（2 分钟）

1. 点击已写入网格任一格子 → 调整对话框：候选列表逐人给出**不可排原因**（有课/时段已满/个人上限）。
2. 添加一人；若该安排构成孤立短节 → 被**拒绝并要求登记例外原因**——填原因后成功（追溯链）。
3. 对某安排点「锁定」；工具栏「撤销」→ 刚才的操作回退（提示撤销会产生违规时会被拒绝——输入变化后旧操作不再合法）。

## 第 4 幕：增量重排的"少改动"（1.5 分钟）

1. 「课程表管理」→ 给某人加一门新课（正落在他的值班时段）→ 影响分析立即列出冲突安排。
2. 回「排班表」→ 模式切「增量重排」（目标周次 1~17）→ 生成：**变动明细表**逐条给出替换与原因（"有课：「新课」"），其余 1000+ 条安排原位保留；若输入没变 → 直接提示"零改动"。

## 第 5 幕：导出与隐私（1 分钟）

1. 「导出第 N 周排班」（含电话开关关一次、开一次）与「导出多周工作簿」（每周一个 sheet）。
2. 讲解点（可打开导出文件展示）：**永不含学号/QQ**；关电话后全表零电话；每节一行带上课时间。

## 第 6 幕：备份与换机（1.5 分钟）

1. 「模板管理」快速过一眼：导入模板试解析、导出模板两套版式 + 版本历史。
2. 「数据管理」→ 导出备份（提示"含个人资料"）→ 从备份恢复：校验摘要 → 数量确认 → 恢复副本自动留存 → 整体替换成功。
3. 收尾语：数据在本机、无账号无网络；升级覆盖安装数据保留；两台电脑用备份文件交接。

## 讲解口径（备查）

- "为什么不会排出上课的人？"——三层防线：生成入口课程占用、手动操作评价器差分、最终独立终态评价（FE-03 修复的 P01~P08 即此类缺陷）。
- "撤销会不会把别人的修改撤销掉？"——每次操作带业务版本（CAS），旧版本操作被拒绝。
- "和直接全量重排的区别？"——增量以现方案为基准，只动被迫变化的部分，输入没变就零改动。
