## 4. 模块设计：只在确有需要处拆分

```text
Vue 页面 / 必要的 composables
        ↓
本地业务服务：导入、课程修改、排班编辑、备份恢复
        ↓
现有 repositories + Dexie 事务
        ↓
IndexedDB

排班请求 → Web Worker → 纯 TS 算法 + 独立评价器 → 方案预览
文件读写 → 现有 fileAccess → Tauri 文件插件 / 浏览器兼容路径
```

- 保留现有目录和公共接口，只对过大的 ScheduleView/CoursesView 按功能拆组件。
- 在现有 db 层按需增加 scheduleService、backupService、courseService；不引入通用仓储框架或后端风格空壳。
- algorithms 保持纯函数，不依赖 Vue、Dexie 或 Tauri；评价器可独立测试。
- Pinia 只管理编辑会话、生成状态和页面共享状态；持久化事实仍在 IndexedDB。
- Excel 解析、哈希、Worker 等耗时工作放在数据库事务外。Dexie 事务仅包含相关数据库操作，避免非数据库异步导致事务提前失活。[Dexie 事务说明](https://dexie.org/docs/Dexie/Dexie.transaction())

## 5. 算法与增量优化

### 5.1 先保证正确，再改善质量

建立独立 evaluateSchedule：重新检查最终结果的课程冲突、重复安排、时段上限、个人周上限、工作区段、连续节次及锁定完整性。生成、手调、恢复为当前排班、增量重排和保存都调用同一评价口径，不能只相信算法内部标记。

默认硬约束：有效人员/时段、无课程冲突、无重复、人数及个人上限、自动安排满足连续节数、有效锁定不移动。覆盖下限及个人目标下限在资源不足时作为显式缺口，不突破硬约束。

原 SRS 允许手动短段：保留为“老师显式选择连续性例外并填写原因”；仅豁免该手动短段，不豁免课程、人数、个人上限，也不能给自动单节提供例外。

节号与实际先后序分离；默认上午 1～4、下午 6～9，每节一行，连续段不能跨不同工作区段。个人上下限按每周的节数计算。

### 5.2 关闭 P01～P08

保留项先校验课程和容量；每日均衡不移动锁定；锁定完整带 weekNo；未知节次展示待核对；参数必须整数、有效星期和范围；旧 8～11 配置不按数值猜测改写；修复/撤销迭代后必须终态再校验，不能留下孤立自动单节。

“手动来源”与“锁定”分开：新手调默认锁定，允许明确解锁；非法锁定给出明细，不静默删除或传播到其他周。每周相同模式需检查各周锁定兼容性。

未导入课表不等于全天空闲。区分缺失、确认无课、可用和待核对；旧记录没有状态时采用可解释的保守回填，并提供确认入口。

### 5.3 保留贪心，增加有限局部改良

不引入 OR-Tools、Python、WASM 求解器。用纯 TS 在合法基线上尝试连续块补齐、移动、交换和有界修复；设置操作次数与总耗时预算，始终保留评价较好的合法结果。

质量优先级：硬约束合法 → 每日均衡开启时减少空白日 → 覆盖缺口 → 个人目标不足 → 增量模式减少变动 → 公平性和所选策略 → 避免多余覆盖。

策略只提供有限预设，例如稀缺空闲优先、身份优先、轮换优先；均不得绕过硬约束。质量报告展示每周缺口、目标不足、负担分布、空白日、改动数及实际耗时。局部改良未改善则保留基线，不宣称全局最优或把启发式失败当作无解证明。

相同输入、seed 和操作预算且未触发时间上限时结果应稳定；触发时间上限记录实际步数与结束原因，不承诺不同机器逐项结果相同。

### 5.4 增量重排

明确选择基准方案、目标周次和全量/增量。有效锁定不动，已有自动安排优先保留；只修改目标范围，合并未变周后评价整份结果。无输入变化且基准已满足前级目标时，增量应零改动。

差异按 (weekNo, dayOfWeek, slot, assistantId) 比较，列出保留、增加、移除、替换和原因。原因采用可验证的课程/规则/人员变化与质量权衡，不伪造算法决策的唯一因果。

### 5.5 Worker 与取消

排班在 Web Worker 运行，主线程负责进度和操作。消息包括 jobId、输入版本、阶段、进度和结果；Worker 不写业务数据库。取消/超时可终止 Worker，旧 jobId 的迟到消息丢弃，取消不修改当前排班。关闭应用后任务结束，下次可重新生成，不承诺关闭后继续计算。[Web Workers 说明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)

## 6. 本地数据可靠性

沿用现有六张表，优先增加可选元数据；确有恢复隔离需要时增加一张 recovery_backup 表，不创建整套服务端领域表。

- config 中维护业务 dataRevision。相关业务写入在同一事务递增；生成预览、编辑与撤销提交携带预期版本。
- 同一读写事务中检查版本再改数据；两个连接基于旧版本写入时最多一个成功，另一个刷新并重新校验。通知只改善界面，不能替代事务检查。
- 单文件导入的助理归档、课程整体替换、版本与日志是一个事务。批次默认允许部分成功；同内容重复不复制，不同文件争同一学生时明确冲突，不按完成先后覆盖。
- 全周期保存用一个跨相关表的事务完成，不能将多次 replaceWeek 当成全周期原子操作。
- 课程编辑与规则/人员变化后，标记旧方案需复核；保存旧预览前重新校验。能够通过当前输入复核的方案不必无条件重新计算。
- 删除助理清理当前课程和排班；历史命名快照保存必要显示信息，避免因删除而损坏。历史恢复缺人/有冲突时阻止直接覆盖，允许只读查看。
- 保留 schema 版本、规则格式版本和备份格式版本的区别；新升级不采用“清空排班再重算”替代数据迁移。

历史 v1/v2 的既有迁移含清空动作；如需兼容这些版本，应在打开新版本数据库前先保全原始数据。本期已发布 v0.1/schema3 升级必须验证数据不丢失。新迁移应事务化、可失败回滚。[Dexie 升级说明](https://dexie.org/docs/Version/Version.upgrade())

## 7. 手调、撤销与历史

手调支持添加、移除、跨格移动、候选筛选、锁定/解锁；每次移动作为一个原子操作。候选显示有课、满额、个人上限等排除原因。安全违规阻止提交，软缺口提示，手动短段例外需明确确认原因。

撤销/重做绑定当前排班的编辑链和版本，默认保留最近 50 步；新编辑截断 redo 分支，撤销也增加业务版本，不能倒退计数或覆盖其他窗口的新修改。相关状态持久化，刷新后验证当前链再恢复按钮。

命名快照固定保存安排、当时规则/时段与必要人员显示信息及输入依据，用于差异、历史导出和受控恢复。旧快照缺少元数据时标记限制，不编造原始姓名或规则。用户命名快照不因普通撤销栈清理被删除。

采用“一份当前排班 + 预览 + 命名快照”，本期不引入完整草稿/发布审批平台。

## 8. 批量导入、课程编辑与模板

支持现有学院网格格式及项目提供的标准明细格式两类导入 profile。用受控字段映射、表头定位、周次/节次/类别词典实现版本配置，不做任意文件通用解析器或脚本插件。

多文件逐项显示文件名、归属、课程数、警告与成功/失败/跳过。标准合法文件仍按学号自动归档，不增加逐人确认。学号按字符串保存，保留前导零；电话/QQ/班级等文件不能提供的字段不被覆盖。

未知条目保留原文和工作表/行位置，进入待核对；同课程号的实验分批和多时段不能被错误去重。批次应有数量/大小限制，逐文件处理并释放缓冲，不同时读取无限文件。

课程页补齐新增、修改、删除，校验周次、星期、节次与类别，保存后列出受影响安排和重新生成入口。

导入模板可试解析后保存新版本；导出模板至少提供学院默认版和简洁打印版，可配置标题、表头、列宽和打印布局。历史快照导出使用其固定信息，不被当前模板/规则变化重新解释。

## 9. 备份、恢复与数据交接

提供版本化结构备份文件（如 .crsm-backup.json），包括助理、课程、当前排班、规则、模板、命名快照、必要日志和格式元信息；校验记录数、唯一键、关联关系、版本及内容摘要。摘要只用于检错，不声称加密或证明来源。

导出先在跨表只读事务取得一致快照，事务完成后再序列化、计算摘要和保存文件。取消文件保存不提示成功，不记录虚假备份时间。

恢复流程：选择文件 → 完整解析/校验/兼容转换 → 显示范围和数量 → 保存当前数据的独立恢复副本 → 在一个事务中替换业务数据 → 重新加载并校验。失败保持原数据，恢复副本不得随主数据清空。可用 recovery_backup 独立表实现隔离，保留策略清楚且避免备份无限递归嵌套。

新版本备份不能让旧版本盲目导入；未知版本拒绝并解释。不得执行备份中附带的 JS、SQL 或任意脚本。恢复后重置不再适用的撤销链，记录来源并提高当前业务版本。

完整备份含个人资料，应明确标注；它不同于对外分发的排班表。当前程序通常不长期保存原 xlsx 文件，备份界面应说明是否包含原文件，不承诺不存在的附件。

两台电脑通过备份导入完成交接；之后是独立副本，不自动同步或合并。首次迁移主交付采用“完整恢复”，避免首版就增加复杂冲突合并。

## 10. 导出、体验和性能

- 单周和多周工作簿、明细和历史快照导出；每节一行，时间标注、电话换行和打印可读性保持。
- 排班导出永不写学号/QQ；关闭电话后遍历所有 sheet 均不含电话，开启时仍只写允许字段。文本按文本单元格处理，不执行公式。
- 首页展示缺课表/待核对、缺口、旧方案需复核和最近备份，点击直达操作。
- 表单保留输入，提交去重；空状态、加载、取消、失败和版本冲突有可行动文案。
- 历史周不因缩小当前规则范围而消失；继承单节网格与声明式弹窗偏好。
- 按实际路由/操作延迟加载 Excel 等重依赖；先测包体、加载和内存，再优化，不仅提高 chunk 警告阈值。
- 50 助理 ×17 周 ×5 天 ×8 节，生成和最终评价目标 ≤5 秒；单份标准课表解析 ≤3 秒；常用页面可操作 ≤2 秒。记录机器、数据、冷/热状态和算法质量，不编造提升比例。

## 11. 离线安装、升级与数据位置

交付一个 Windows x64 NSIS 安装包。前端资源、帮助、样式和所需字体均本地提供，不使用必需 CDN、在线许可证验证或远程接口。

特别验证 WebView2：Tauri 默认的下载引导方式依赖网络。主方案采用其 offlineInstaller 配置，把完整运行时安装程序随包携带；不能只使用 embedBootstrapper 就声称支持首次断网安装。[Tauri Windows 安装说明](https://v2.tauri.app/distribute/windows-installer/)

保持应用 identifier=com.crsm.app、数据库名 crsm 和存储 origin 连续，避免升级后看似“空库”。安装应用到 D 盘不等于 IndexedDB 自动搬到 D 盘；数据由 WebView 用户目录管理，备份文件可以另存 D 盘。

升级和默认卸载行为需明确数据保留策略；至少验证覆盖安装后原数据可用。清除业务数据是独立、明确的操作。浏览器开发环境和桌面 WebView 的数据不自动共享。

干净 Windows 机器断网、无开发工具、缺少 WebView2 时，安装→首次启动→导入→排班→手调→保存→重启→导出→备份→另一台机器恢复，整条流程必须有实际证据。前端 build 通过不等于安装验收通过。
