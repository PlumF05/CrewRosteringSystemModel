## 技术与范围

按详细计划采用以下基线：

- 保留 Vue 3 + TypeScript + Element Plus 前端，逐步清理大组件和本地数据库耦合。
- Django + DRF + PostgreSQL，使用 Django ORM/migrations；初始验证 Django 5.2 LTS、Python 3.12 与受支持数据库版本，锁定实际兼容版本。
- 纯 Python 排班内核，**修正版贪心和 OR-Tools CP-SAT 两者都要完成**，共用输入模型及独立评价器。
- Celery + Redis 处理求解、批量导入和较大导出；PostgreSQL 持久记录任务、结果及 outbox。
- 同源 Session + CSRF、固定三角色及学期/本人权限；OpenAPI、自动测试、Docker Compose、备份恢复。
- 服务一个学院办公室，优先完成主业务，不扩张到微服务、多租户计费、Kubernetes、工资/考勤或 AI 对话功能。

如遇真实依赖兼容问题，可做有证据的小范围调整并记录 ADR；不要重新讨论整套技术路线而不实施。

## 不能出错的关键协议

- 值班量按每周“节数”计算；节号与真实先后序分离，默认上午 1～4、下午 6～9，每节一行，连续段不跨午休。
- 未提交课表不是全天空闲；ready、确认无课、缺失、待核对分开；未知节次不能静默丢弃或显示“已安全”。
- 课程/批准请假冲突、时段上限、个人上限等安全约束不能通过手动来源或锁定绕过。原始手动短段例外必须明确标记、填写原因，只豁免连续性。
- 每个求解结果和业务修改都独立评价。缺口可以报告，不能为了填满而产生违法安排；修复审查 P01～P08，不把错误输出固化为新期望。
- 有效锁定带明确周次，不能被均衡搬移；手动来源与锁定分离。增量重排优先保持稳定，同时遵守计划定义的覆盖和硬约束优先级。
- 单学生导入事务原子，批次逐项返回；文件/数据库边界可恢复，重试幂等，同批不同文件争同一归属不能随机覆盖。
- `input_revision`、草稿 `lock_version`、正式发布修订号分开。输入变化标记过期，草稿修改使用版本条件更新；发布在一个数据库事务中校验输入、生成整份修订并更新当前指针。
- 求解在长事务外执行，但输入快照必须一致。两次并发发布最多一个基于旧版本成功；旧版本永不原地改写。
- outbox 持久投递、任务幂等、租约/执行 token 防旧 worker 覆盖；不要宣称消息队列天然保证业务恰好一次。
- 任何排班导出都不写学号/QQ；电话只由服务端权限控制。使用脱敏/合成测试数据，不复制历史真实学生信息到演示或报告。

## 执行安排

把详细计划的 M0～M9 拆为可执行子任务，建立并持续更新：

- `docs/implementation/TASKS.md`：任务、依赖、状态、相关文件/提交和下一步。
- `docs/implementation/ACCEPTANCE.md`：F01～F08、P01～P08、增强能力、A01～A32 的实现与验证映射。
- `docs/implementation/VERIFICATION.md`：实际执行命令、环境、结果、未运行项及证据位置。
- `docs/implementation/DECISIONS.md`：业务默认值与重要 ADR 索引。

顺序按 M0 基线 → M1 全栈纵切 → M2 可靠导入 → M3 评价器/贪心 → M4 手调/版本发布 → M5 CP-SAT/增量 → M6 任务恢复 → M7 学生协作 → M8 双模板/迁移恢复 → M9 交付执行。可按依赖调整相邻工作，不得删掉难项来缩短目标。

每个阶段交付可运行切面并验证，完成后自动继续。上下文不足或切换会话后，从任务台账和验收矩阵恢复，不重复从零规划。发现问题及时修正并更新计划，不让文档与代码分叉。

常规实现选择按详细计划默认值自主解决。真正依赖缺失业务资料或外部环境时，说明具体阻塞、已经完成的独立工作与最小所需信息；不能编造结果。Docker/数据库未可用时可先做纯域和代码工作，但不能用 SQLite/mock 冒充 PostgreSQL 并发或部署验收通过。

保存当前工作与旧数据，使用专用开发分支、适度提交，不强推或重写历史。公共发布、真实数据迁入、凭据和外部通信只按实际授权进行；不要因普通本地实现而逐模块请求继续许可。

## 验证与完成标准

详细计划 A01～A32 是必验清单，至少包含：

- 纯域/解析/连续段/锁定/评价器测试，小规模穷举与随机不变量，固定算法基准；CP-SAT 至少有一个可验证优于修正贪心的实例。
- PostgreSQL 真事务/独立连接并发：导入回滚、输入快照、编辑 CAS、双发布、调班幂等和旧 worker 提交。
- API 真实权限/CSRF/列表过滤/文件下载和所有关键状态转换。
- Vue 端到端老师主流程、学生手机流程、部分失败、过期/409、历史导出。
- 消息失败、重复投递、进程重启、取消/重试、全新卷备份恢复演练。
- 空环境启动、数据库升级迁移、CI、构建与性能记录。

原始基线为 11 文件 162 个前端用例通过、前端构建通过，但这不代表业务完整或无缺陷。最终以新业务验收和故障验证为准，不以测试数量或文件数量作为成果。

性能口径采用详细计划：50 人 ×17 周 ×5 天 ×8 节，快速排班计算 ≤5 秒；标准单课表解析 ≤3 秒；主要页面可交互 ≤2 秒。优化模式给明确预算和真实状态。记录硬件、环境、测量范围，不能编造提高比例。
