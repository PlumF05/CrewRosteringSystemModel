## 2. 当前架构与已有价值

当前是 Vue 3 + TypeScript + Element Plus + Tauri 2 的单机桌面应用；使用 Dexie/IndexedDB，数据库版本为 3，包含六张表；没有 Python 服务、服务端数据库、登录授权或多人协作。

已经形成可用的主链路：单份 Excel 课表解析 → 按学号自动创建/更新助理 → 整体替换其课程 → 按周贪心排班 → 全周期预览与差异 → 按周写入 → 单周带样式 Excel 导出。节次顺序、周次区间、课程类别、个体值班上下限等已有不少业务积累。

值得保留的是纯函数算法边界、学院课表的解析规则、数字与命名节次的映射、回归样例、单节网格和现有交互习惯。需要升级的是业务完整性、算法正确性、协作一致性和服务端工程能力。旧版本“本地存储、无登录”符合当时需求，不能把这些既定选择直接写成旧版缺陷。

## 4. 可复现的算法与边界观察

复现方式：先安装当前前端依赖，然后运行：

```powershell

```

脚本只读取源码并用合成数据运行纯函数，不写数据库、不读取真实课表、不修改业务代码。结果保存在 [audit-baseline-results.json](audit-baseline-results.json)。**脚本返回 0 只表示探针成功运行，不表示项目通过正确性验收。** JSON 中 `findingObserved: true` 表示观察到了待处理行为，不能把这些行为作为未来实现应保留的正确断言。

| 编号 | 观察与最小场景 | 证据性质与影响 | 目标处理 |
| --- | --- | --- | --- |
| P01 | `keep` 中保留某人有课的第一节，输出仍包含该安排 | 算法入口实测；手调 UI 尚缺，属于潜在集成路径，不等于已复现普通用户点击造成冲突 | 锁定项进入统一可用性校验；冲突锁定给明细并阻止发布 |

| P03 | 两天、每人上限一节，把两条手动保留集中在第一天；每日均衡将其中一条搬到第二天，来源改为 `auto` | 算法实测；保留语义与再平衡冲突 | 手动来源与锁定分离；有效锁定不参与自动搬移 |

## 5. 静态设计风险与产品缺口

下列是源码分析结论，**本次没有通过故障注入或多人 GUI 测试证明已经发生数据损坏**：

1. `src/db/importService.ts` 先更新/创建助理，再替换课程并写日志，缺少覆盖整次业务操作的外层事务；中途失败可能留下部分更新。
2. `replaceWeek` 的单周替换已有事务，但 ScheduleView 的全周期保存是逐周调用；不能把“每周原子”当成“全周期原子”。
3. 人员、课程和规则缺少学期范围及输入快照；已排结果不能完整追溯到当时的课程和规则。
4. 排班记录被直接替换，没有草稿与发布版本、并发编辑版本号、发布门禁和不可变历史。
5. 缺少“未提交课表”和“确认无课”的区别；未知节次、历史迁移歧义缺少显式的数据质量状态。
6. 缩小当前规则周次后，历史周的可发现性需要处理；单节网格的行/列并集修复不等于周次列表也已覆盖历史。
7. 首页主要是数量和最近操作，尚未提供课表缺交、排班缺口、版本过期、待审批等可行动信息。
8. 没有服务端事务、授权、后台任务、故障恢复、PostgreSQL 并发集成测试和完整 Web E2E 的工程链路。
9. 当前构建存在大分块警告；Excel 相关依赖与路由加载边界需要测量后优化，不能靠提高警告阈值宣称优化完成。
10. 文档对功能完成度、样例、版本和测试数量有漂移。历史需求中的单机/无登录，应在新增全栈需求中明确替代关系，保留历史解释。

## 7. 对完善方向的结论

项目的提升空间主要在四个方面：**带独立校验与质量证据的约束求解、保持稳定的增量重排、带输入快照和并发控制的发布版本、可重试且可恢复的数据导入**。再用学生提交/请假/调班审批串起真实使用流程，并完成部署、备份恢复和学习材料。

这些能力都来自现有业务，适合作为能够解释、演示和验证的项目经历。单纯增加几个 CRUD 页面、换数据库，或堆叠不需要的中间件，不能解决本次审查发现的问题。
